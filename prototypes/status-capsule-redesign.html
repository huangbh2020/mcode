聊天区右上角 · 活动胶囊重设计(四方案)

对象:StatusCapsule.tsx(玻璃药丸:计划 ×N ｜ 子代理数 ｜ 任务 done/total ｜ 书签数)+ ActivityPopover.tsx(384px 四段竖排叠栈弹层)。

核心问题:药丸上只有数字没有状态——运行中"此刻在干什么"必须点开才知道;弹层四段竖排在内容多时又长又挤;四类活动视觉权重相同,当前"热"的活动不突出。

下面四个方案共用同一份场景数据,收起态、运行态、展开态都可交互。所有方案均保留:子代理行 → 右侧 transcript、计划标题 → PlanDrawer、书签 → 定位消息、BookmarkFly 落点锚点、数字变化弹跳;移动端 ActivitySheet 做等价形态。

点击胶囊 / 分段试试展开;悬停 chip 看预览

药丸 = 图标 + 计数,弹层 = 四段竖排。问题一目了然:五段挤在一起时"哪段在动"靠一颗小脉冲点,悬停无任何预览。

现状 · 仅示意收起态
  • 有数字、无状态:子代理段只有 "2",在跑哪个工具/什么描述要开弹层滚到子代理段才能看到。
  • 弹层是竖排叠栈:四段全展开时高度轻松超 600px,找"任务"要滚过计划和子代理;折叠状态能记住但导航成本仍在。
  • 权重无差别:书签(冷数据)与运行中子代理(热数据)占用同样的视觉重量。
  • 任务进度不可读:"2/7" 要心算百分比;完成过程中没有可视的进度感。

方案 A · 仪表分段 + 页签弹层

A · gauged segments, tabbed popover

对现状的最小进化:药丸保持一颗,但子代理 / 任务两段各升级为一枚 15px 微进度环(任务 = 完成度弧,子代理 = 运行占比弧);弹层从"四段竖排叠栈"改为分段页签——顶部一排页签(带计数,运行中的页签闪一条琥珀横杠),下方单内容区。热活动(运行中)默认选中页签。

学习成本最低(形态延续现状) 弹层高度恒定,导航 O(1) 微仪表让进度一眼可读 收起态信息量提升有限(仍是数字为主) 改动范围:胶囊两段 + 弹层壳,四个分段组件基本复用
方案 A · 点药丸展开;点页签切换

方案 B · 纵向活动栈

B · vertical live dock

换一个结构哲学:取消弹层。右上角变成一列右对齐的独立 chip(每类活动一根),运行中的 chip 上直接显示当下——子代理 chip 内嵌"工具 · 目标"实时条,任务 chip 内嵌迷你进度条。悬停展开一行预览(正在跑什么),点击 chip 原地向下展开迷你卡片(手风琴),不再有浮层。回合结束后整列降饱和为冷色档案态。

运行状态"零点击"可见(信息最即时) 无浮层,展开不遮挡消息流中心 各类活动天然分组,互不挤压 纵向占高;满载时(4+ 类)右边缘变"仪表墙" BookmarkFly 落点从"一颗药丸"变"一根 chip",锚点要改 改动范围:胶囊整体重写;弹层四个分段组件改造为手风琴卡片
方案 B · 悬停 chip 看预览;点击原地展开

方案 C · 单体指挥卡

C · unified command card

取消"收起 / 弹层"二段式:右上角常驻一张玻璃卡。卡内自上而下:活动脊线(四类活动的相对体量,任务段内嵌完成度填充)→ 四格指标(点击切换焦点分区)→ 实时操作行(正在跑的工具/代理,流光点缀)→ 焦点分区内容。点右上角箭头整卡收成 264px 的"指标条"——即现状药丸的完全体。一张卡内完成收起 ↔ 展开的连续变形,没有第二个浮层。

单一形态,心智最简单(无"开窗口"感) 实时操作行把"当下"常驻在聊天视野里 脊线 + 四格指标 = 全局体量与进度一眼可读 展开态占位最大(300px 宽),与长代码块争宽度 改动范围:最大——胶囊与弹层合并重写为一卡;但行组件全部复用
方案 C · 点四格指标切分区;点箭头收成指标条

方案 D · 轻锚点 + 宽导航弹层

D · minimal anchor, two-pane navigator

反方向压到极致:收起态只是一枚 34px 圆钮(活动总数角标 + 底下四根按各类数量定高的迷你 spark 柱,运行中套一圈旋转琥珀弧)。弹层则扩张为 576px 双栏导航:左栏 = 四类活动的导航轨(计数 + 运行中直接列出代理名),右栏 = 选中类的完整列表(行更宽敞,统计 chip 不再折行)。为"重会话"(十几个子代理/任务/书签)而设计。

收起态最安静(不与内容争视觉) 双栏导航,大列表浏览效率最高(IDE 感) spark 柱把"会话都发生过什么"压缩进 34px 收起态信息最少,运行感知靠角标+弧,弱于 B/C 576px 弹层在窄中栏可能放不下(需宽度降级) 改动范围:弹层壳重写为双栏,行组件原样搬进右栏
方案 D · 点圆钮展开;点左栏导航切换右栏

推荐组合拳:主体走 D(圆钮锚点 + 双栏导航),把 A 的微进度环嫁接到 D 收起态(圆钮内圈即任务完成弧,替代 spark 柱之一),B 的"实时操作行"作为 D 展开态右栏顶部的可选行——三者不冲突。若想先小步验证,A 是最稳的第一步。
不做什么:四个方案都不把弹层做成常驻右栏(右侧已有 sidechat / 计划抽屉 / diff,不能再抢);都不引入每秒 tick 的重渲染(运行时长走现有 1s ticker 的既有订阅)。
