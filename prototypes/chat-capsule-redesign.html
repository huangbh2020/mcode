聊天区右上角「活动胶囊」· 重设计四方案

现状是 StatusCapsule.tsx 的一颗玻璃药丸：absolute right-8 top-2 浮在消息流上方， 内部最多四段「图标 + 数字」并列（计划 ×2 │ 子代理 3 │ 任务 4/7 │ 书签 1），点开是 384px 的 ActivityPopover；有子代理在跑时药丸后面呼吸一层琥珀光。四个方案都认同下面的问题清单， 区别在于改哪一层：只改表达（A）、改宿主结构（B）、改信息架构（C）、改摆放位置（D）。

1图标 + 数字不可读四段都不带文字，含义只存在于 title 里；新用户第一眼读不出「📋×2」是什么。
2语义混排书签是用户手动收藏的导航锚点，子代理/任务是模型此刻的运行时状态——同权并排，一颗胶囊又当监视器又当收藏夹。
3优先级倒置计划段总排第一，真正紧急的「运行中」埋在中段，只有一颗 5px 小圆点在脉冲。
4遮挡正文绝对定位浮在消息上方，首条消息的正文被压在玻璃下面（见「现状」里的 ④ 标记）。
5进度不可见任务段只有 4/7 这个分数、没有进度条；计划只有个数，看不出哪一份属于当前回合。
6容量与窄栏窄栏（宽屏 3:7 / 侧栏展开）时四段加箭头挤到 250px+，与正文争宽度；竖排又只能容四类。

基线现状：四段图标 + 数字，浮在右上角

下面这颗就是现在的实现（结构与类名照搬）。①–⑥ 的标记对应上面那组问题；④ 标在正文上， 把「列宽」拉到 380px 以下还能看到 ⑥——窄栏里药丸几乎横跨半个内容区。

在聊天里（实时列宽）
  • ① 段内只有图标与数字。「☰ 4/7」得 hover 才知道是任务，触屏上连 title 都没有。
  • ② 书签与运行时状态同权。书签是用户资产（持久、可改名、可删除），子代理/任务是模型此刻的过程；混在一颗胶囊里，按下它去"看进度"会先撞到一堆收藏。
  • ③ 计划排第一。计划多的会话里，"运行中"被推到第三段，唯一提示是一颗小圆点。
  • ④ 遮挡。玻璃药丸压在消息正文上；会话开头那条最长的段落正好在它下面。
  • ⑤ 任务只有分数。4/7 需要心算；展开浮层里才有一条整体进度条。
  • ⑥ 窄栏拥挤。四段 + 分隔线 + 箭头在 wide 模式（聊天只占 30%）下与正文争宽。
  • 另外，四类全空时整颗不渲染——这一点四个方案都保留，是好的。

方案 A状态条 · 保守增强

位置与形态完全不动，只把表达修好：按紧急度重排（运行中 → 任务 → 计划 → 书签）、 给活的那一段配文字与琥珀色、任务段加一条 2px 进度下划线、任何一段 hover 展开文字标签； 窄栏时计划与书签自动退到浮层里，只留「实时 + 进度 + 箭头」。改动最小、可以当天上。

在聊天里（实时列宽 · 悬停任一段可展开文字）
  • 重排。运行中的子代理永远第一段并带文字「2 运行中」；没有运行中时退化成安静的「🤖 3」。
  • 进度下划线。任务段数字下方一条 2px 进度条，一眼看出还剩多少，不用心算 4/7。
  • hover 出标签。复用 composer 的 1fr↔0fr 网格壳，悬停时逐段展开文字，静止时仍然紧凑。
  • 书签让位。换成更粗的分隔线 + 降透明度（0.62），读起来是"另一个世界的东西"，不再与实时状态平权。
  • 窄栏让位。列宽 < 520px 时计划/书签段隐藏，进入浮层；药丸只剩「实时 + 任务 + ⌄」，宽度降到底。
  • 没解决的：④ 遮挡与 ⑥ 容量上限（仍然最多四类、仍然浮在正文上）。这是保守的代价。
三种数据状态
展开态（点击药丸）
  • 顶部多一行实时摘要。「2 个子代理运行中 · 任务 2/5 · 已跑 1m12s」——即使不展开也知道胶囊在报什么。
  • 运行中的子代理置顶并带进度条；已结束的排在后面，不再混排。
  • 段落顺序与药丸一致（实时 → 计划 → 任务 → 书签），从药丸到浮层不发生一次"位置重排"的认知跳跃。

方案 B停靠台 · 胶囊变成一根真实台头

不再浮在正文上：在消息流上方放一根 34px 的真实布局行（左侧实时摘要、右侧带文字标签的索引）。 横向空间足够，标签常驻不必 hover；彻底消灭 ④ 遮挡与 ⑥ 窄栏拥挤。代价是常占一行高度， 所以配一个「滚动后收起成 2px 进度线」的行为把空间还回去。

在聊天里（实时列宽 · 台头行占布局）
  • 左：实时摘要。琥珀点 + 「2 个子代理运行中」+ 12 步 + 1m12s。这是"现在在干什么"的常驻答案。
  • 右：带标签的索引。「计划 2」「任务 2/5」都是常驻文字，不需要 hover、触屏也可读。
  • 任务 chip 自带进度底纹：chip 内部下沿 2px 进度条，分数之外多一层直观读数。
  • 占用与位移。34px 是常驻成本；四类全空时整行不渲染，所以会话里"活动出现/消失"会有一次高度变化。
  • 滚动收起。离开顶部后整行高度归零，只在顶边留一条 3px 进度线（截图里的第三种状态）；回到顶部或向上滚动时展开。
  • 窄栏也成立：标签在极窄时收成图标 + 数字（复用同一套 lblwrap），行永远不换行不换高。
三种数据状态（含滚动收起形态）
展开态（点击右端箭头，从台头右侧垂下）
  • 浮层内容与方案 A 同构（实时摘要 + 运行中置顶 + 计划/任务/书签），差别只在锚点：从台头右端垂下，不再浮在正文里。
  • 因为台头本身已经表达了"有什么、多少"，浮层在这里更像下钻而不是"探查"，宽度也可以更窄。

方案 C指挥台 · 实时与资料分家

不换位置、不占布局，但把信息架构拆开：左边一簇只说"此刻在跑什么" （运行中的子代理头像 + 任务环 + 走时），空闲时整簇消失；右边一颗安静的 ⋯ 资料按钮收纳计划、已结束的子代理、书签。改动集中在语义与状态机，遮蔽问题维持现状（但元件更小更靠边）。

在聊天里（实时列宽）
  • ② 语义分家的落地。实时簇是"监视器"（会自动出现、自动消失），⋯ 是"资料柜"（用户资产与历史，永远在）。
  • 空闲态最安静。没有运行中的东西时整颗只剩「⋯ 6」——比现在的四段安静得多，右上角不再有噪音。
  • 实时簇可读。带琥珀色、头像、16px 环形进度与走时；一眼即知"两个子代理在跑、任务六成"。
  • 位置不漂移。⋯ 钉在固定的右端，实时簇向左生长（justify-content:flex-end），出现/消失不会挪动 ⋯ 的位置。
  • 两个目标要学。用户先要知道"实时在左边、资料在右边"；用一周的首次提示缓解。
  • 没解决的：④ 遮挡（但最常用的"看进度"路径不再需要开浮层，遮挡影响变小）。
三种数据状态
展开态（点击 ⋯ → 顶部两个页签）
  • 页签「运行中 2」：只有正在跑的子代理 + 进行中的任务，行短、信息密度低、可以常开。
  • 页签「资料 9」：计划（含"本轮"标记）、已结束的子代理、全部任务、书签。这是"回头看"的地方。
  • 已结束的子代理从实时区移走后，实时页签的行数天然有界，不会随会话变长而越堆越多。

已选方案 D右缘轨 · 与左侧时间轴对称

把胶囊从"右上角的点"改成"右边的一条轨"：竖排 26px 圆形节点贴住聊天列右缘，垂直居中， 与左缘已有的用户消息时间轴形成对称——左边是"你去过哪里"，右边是"agent 正在做什么"。 零遮挡、容量纵向展开；代价是与右面板争夺边缘，且标签只在 hover 时出现。

在聊天里（实时列宽 · 静止态；悬停浮出标签见下方状态一览）
  • ④⑥ 一次解决。轨道竖排、只占 26px 宽，永不与正文重叠，也不参与横向竞争。
  • 容量天然够。四类节点只占约 130px 高，将来加"本轮文件""检查点"等新类别也只是多一颗节点。
  • 与左缘时间轴对称。左灰/金短划线（消息与书签）↔ 右玻璃圆点（计划/子代理/任务/书签），一条消息走廊。
  • 进度直接做在节点上：任务节点外圈的 conic 进度；运行中的子代理节点带 amber 光环脉冲。
  • hover 浮出标签卡，子代理节点还会直接列出最多两条运行中的行（不必开浮层就能看描述）。
  • 触屏没有 hover。移动端仍走现有底部抽屉（ActivitySheet），此处只影响桌面。
  • 窄栏挤压。26px 轨道要从聊天 gutter 里让出来；wide 模式（聊天 30% 宽）下最紧张，需要把 gutter 收到 12px。
  • 锚点溢出。节点在右缘，浮层必须向左展开，窄栏时容易撞到中心；需要一次"左/右翻转"判定。
三种数据状态
展开面板「活动台」· 四种节点各一张（点击右缘节点向左浮出，缺口对准该节点）
  • 不再是"一列清单"。统一壳是五段：头部（节点身份 + 实时摘要 + 在右栏打开 / 关闭）→ 汇总条（该类的聚合指标）→ 筛选 chip（带计数）→ 分区正文 → 页脚动作。四类节点共用骨架、各自的强调色与正文形态不同。
  • 子代理 = 时间轴。每条代理在会话时间轴上按真实起止铺一条 4px 条形，运行中的条一直顶到右侧的「现在」刻度并呼吸；行内是类型徽标 + 状态 + 起止时钟 + 描述/结果/错误 + 指标 chips。st/dur 来自运行台账的同一份数据，不是装饰。
  • 把「实时 / 资料」拆分搬进面板。运行中与已结束分区，筛选 chip 可只看运行中；已结束的排在后面 —— 面板在小尺寸下也有了方案 C 的信息架构。
  • 任务 = 看板。34px conic 环 + 按状态着色的分段进度（一段一项，完成绿 / 进行中琥珀）+ 剩余项数；正文按 进行中 / 待办 / 已完成 分组，每行保留优先级色条，完成的划线降调。
  • 计划 = 索引。序号芯片 + 标题 + 两行摘要 + 生成时间，最新一份带「本轮」标记；书签按 今天 / 更早 挂在一条竖向细线上（与左缘消息时间轴同一语言），失效项灰掉但保留位置。
  • 锚点与翻转。面板固定 404px、从节点向左浮出，缺口对准被点节点；窄栏（聊天列 < 460px）时必须翻到右侧或改成底部抽屉，这是实装时要处理的边界。

已选方案 D，展开面板重做为「活动台」。面板骨架是五段——头部（节点身份 + 实时摘要 + 在右栏打开）、汇总条、筛选 chip、分区正文、页脚动作； 四类节点共用骨架，正文按数据类型换形态：子代理是会话时间轴（每条代理按真实起止铺条形，运行中的顶到「现在」刻度），任务是将状态着色的看板， 计划是带两行摘要的索引，书签按今天/更早挂在竖线上。原方案 C 最值钱的那条——「实时 vs 资料」的语义拆分——被搬进了面板内部 （运行中/已结束分区 + 筛选 chip），所以这次没有丢掉它。 实装时优先处理两处边界：面板在窄栏要翻转到右侧或退化成底部抽屉（复用现有 ActivitySheet）；移动端不依赖 hover，点节点即开面板。
