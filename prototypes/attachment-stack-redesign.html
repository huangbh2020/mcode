附件卡 · 配色优化 + 苹果式堆叠

范围:用户消息流中的附件卡(文件 / 粘贴 / 引用,即 AttachmentCard,含上一轮的合并 chip 行)。 目标:① 文字不再直接使用品牌强调色;② 多卡时收拢为可点击展开的堆叠(iOS Wallet / 通知堆叠质感)。 主题令牌取自 styles.css 实值,右上角可切换明暗主题预览。

堆叠卡片均可点击体验展开 / 收起
一、卡片配色 2 个候选

现状:边框、底色、文字、图标四层全部吃强调色,信息未选中也在"高喊"。iOS Messages 的做法是 气泡上的附件 = 中性纸面小卡:白底、灰边、中性文字,只有选中 / 打开态才回到品牌色 —— 与气泡的品牌色底形成 "彩色信纸 + 白卡片"的层次。以下两个候选都把文字降为中性,区别在图标与底色保留多少品牌气息。

二、多卡堆叠 · 点击展开 3 个形态 × 可交互

≥2 张卡时收拢为一叠:顶卡 = 第一张附件(真实可交互卡),身后 1-2 层卡背伪影,右上角骑缝计数徽标。 点击堆叠展开为现有 chip 条(逐卡弹入),行尾「收起」回到堆叠。收起态只渲染顶卡 + 装饰层, 不渲染真实卡 —— 与实现方案一致,展开行省掉堆叠里已有的那张。

三、交互与实现细则
  • 堆叠阈值:≥2 张卡。单卡保持普通 chip;堆叠只影响消息流附件行,输入框 composer 的 chips 条不堆叠(那里是"待编辑"语义,需要全部可见可删)。
  • 点击堆叠 = 展开(命中区含徽标);展开后行尾「收起」pill 收回(镜像代码块折叠 pill,两个折叠面读感一致)。顶卡不拦截点击 —— 收起态点顶卡是展开,不是打开文件,避免误触开 IDE。
  • 展开动画:高度 grid-rows 0fr→1fr 过渡 + chips 逐个弹入(composer-tag-in 同款 spring,每张 +40ms 阶梯);收起反向。prefers-reduced-motion 降级为直切。
  • 历史持久:不持久化展开态——重开会话默认收起(堆叠即"摘要",展开是临时查阅)。与 5 行折叠的模块级展开集合同思路,可选做成 Set。
  • 与折叠预算的关系:堆叠在媒体组内(上一轮的媒体豁免),高度恒为一枚 chip + 8px 卡背,永远不会触发 5 行折叠;展开态同理。
  • 外部文件不可查看的 toast、图片卡预览、文件卡直开 IDE 等既有交互全部保留 —— 堆叠只是容器形态,不碰单卡交互。
  • 选中态 = 打开中的卡保留强调色描边 + 柔光(方案 A 内唯一品牌色时刻);徽标配色中性(zinc-500 底白字),不参与品牌色。
  • 暗色主题:同样的令牌替换(卡面 --surface、边 --edge、文字 --content-muted),右上角切换可直接预览。
推荐组合:配色 A(中性纸面)+ 形态 V1(垂直堆叠)。 理由:白卡浮在品牌气泡上是 iOS Messages 验证过的层次模型,品牌色退到"只出现在激活态";V1 无旋转、最稳重,与既有手绘主题和代码块折叠 pill 的克制气质一致。 若想要更活泼,可选 B + V2。确认后我再落到 AttachmentCard / AttachmentRow / MessageRow 媒体组 的实现。
