0现状基准

按当前 LeftBar 的结构 1:1 模拟(置顶项目 / 置顶会话两个独立小节、单行会话、树线缩进、hover 交换图标切 worktree 视图、底部归档桶),作为对照基线。

观察到的问题

  • 六层结构一列等价堆叠:置顶项目 → 置顶会话 → 分组 → 项目 → worktree 组 → 会话,行高/图标尺寸几乎一致,层级全靠缩进和树线撑
  • 两个置顶小节头(uppercase)占了双份 chrome,内容却常常只有 1-2 行
  • 单行会话右侧三态切换(时间 ↔ 未读 ↔ hover 操作),信息塞得满但扫读性一般
  • worktree 视图入口是 hover 才出现的交换图标——最强差异化功能却不可见
  • 归档桶常驻底部,随数量无限长高
基准仅用于对比,无参考来源。

A分层树 — 保留信息架构,重建层级感

  • 置顶合一:项目+会话合并进一个「置顶」卡片(微弱 accent 底色),类型靠头像/圆点区分——砍掉两个小节头
  • 项目行升格:彩色头像 + 名称 + 「4 本地 · 2 工作树」元信息行,子会话计数/运行态在父行可见,不用展开就知道里面有什么
  • 会话两行制:标题行 + 元信息行(provider 点 · 分支 chip · 时间),状态(未读/运行)固定右侧;选中态从树线改为左侧 accent 竖条
  • 工作树变泳道:内嵌圆角卡片,分支名 mono chip + 合并状态点(琥珀=有未合并,绿=已合并),hover 出「合并回 / 新建」——取代隐藏的交换图标
  • 时间微分组:项目内按 今天 / 昨天 分段,找回时间坐标
  • 归档压缩:单行虚线入口 + 计数,点开弹层而非常驻长列表

代价

  • 两行行高让同屏会话数 ↓ 约 30%(可用紧凑模式兜底)
  • 实现改动集中在 LeftBar 表现层,数据/store 不动——迁移成本最低
适合:想保留「项目树」心智、只求更清晰更有质感。
推荐作为默认落地形态。
参考:Linear 侧栏层级 / GitHub PR 列表行 / T3 Code 项目 favicon 头像。

B时间流 — 会话是主角,项目退居切换器

  • 项目 → 顶部切换器:头像 + 名称 + 概要,下拉含「全部项目」与分组;侧栏不再有项目树,整列都是会话
  • 全局时间分组:置顶 / 今天 / 昨天 / 更早——跨项目统一的时间坐标,和 ChatGPT/Claude 桌面版同构
  • 全部项目视图:每行带项目头像前缀,一屏纵览所有进行中的工作
  • 过滤 chips:全部 / 运行中 / 工作树——把「运行中」从逐行找 spinner 变成一键聚焦
  • 工作树降为目录对象:会话进时间流(meta 带分支 chip),底部「工作树」区块只列目录状态与合并入口——会话与合并单元各归各位,不再混排

代价

  • 项目间跳转多一次点击(切换器);「按项目聚合」的心智被替换
  • 与现有 tabs 模式的会话 tab 栏存在概念重叠,需要梳理
适合:多项目并行、以「任务/线程」为中心的使用方式,最接近 T3 Code / Codex 桌面版的主流形态。
参考:T3 Code / OpenAI Codex 桌面三栏(项目↔会话分离)、ChatGPT 时间分组、Slack DM 分节。

C双栏工作台 — 图标轨 + 会话列

  • 54px 图标轨:项目头像纵排(Discord 式),激活 = 左侧 accent 指示条 + 光环,置顶 = 角标 pin 点;轨道底部沉设置/主题
  • 会话列只服务当前项目:项目名头部(路径副标题)+ 新会话 CTA + 时间分组 + 工作树泳道——每列职责单一,再无六层堆叠
  • 「全部项目」= 轨道顶部圆点:列表切跨项目混排(行前缀项目头像),B 方向的时间流可作为该视图的分组方式
  • 分组「工作」在轨道上以头像右下角色点表达(或轨道 hover 提示)

代价

  • 总宽 ~300px 且结构变动最大:拖拽排序、分组菜单、归档弹层都要重新安置
  • 项目数很多时轨道会溢出(>10 个项目需要滚动/收纳)
适合:想要最「IDE 工作台」气质、愿意为结构变化买单;也可以只取「轨道」作为未来工作区切换器的种子。
参考:Arc 侧栏 / Discord 服务器轨 / Raycast 根栏。
