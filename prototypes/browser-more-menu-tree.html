冻结的页面快照(菜单打开期间 OS view 暂停)

现状问题

  • 现状三段平铺:全屏切换 + 收藏段(max-h-44)+ 历史段(max-h-44),两个列表互相挤压,收藏一多历史就只剩几行,反之亦然。
  • 现状「收藏此页」「清空历史」藏在分段头部的小字按钮里,动作与列表混杂,不易发现。
  • 现状下载条只有底部临时条,没有历史入口;browser.clearCache RPC 已存在但无 UI。

方案 A · 树形折叠面板(推荐)

  • 一级动作:收藏此页(星标态)/ 展开全屏 —— 最高频操作不再藏进分段头。
  • 三个可展开节点(多开,非手风琴):收藏 / 历史记录(按 今天·昨天 分组)/ 下载 / 隐私与缓存。一次只关注一类,列表各自滚动。
  • 节点头计数徽标 + hover 快捷动作(收藏 +、清空历史 🗑、打开下载目录);条目行 hover 出现 打开新标签 / 删除。
  • 下载节点显示实时状态(下载中进度条 / 已完成),与底部 DownloadBar 同一数据源。
  • 交互成本最低:仍是单击开 → 单击选,键盘 ↑↓ 移动、→ 展开、← 收起、Esc 关闭。

方案 B · Chrome 式级联

  • 根菜单极窄(200px),hover「收藏 / 历史 / 下载」向左弹出子面板(右锚定,左侧是页面快照区,空间足够)。
  • 优点:视觉最像桌面浏览器,根层干净。
  • 缺点:hover 级联在触摸板/精确度差时易滑出;子面板与根菜单 两块浮层都要盖在冻结快照上,遮挡判定与 Esc 处理翻倍;窄侧栏下子面板宽度预算紧张。

共性约束(两个方案一致)

  • 数据源零改动:bookmarks / history 仍是 settings 表既有 key,下载复用 DownloadBar 的注册表。
  • freeze 契约不变:开合仍走 onMoreMenuOpenChange,弹层是同层 renderer DOM,浮在冻结快照上。
  • 条目点击走既有智能打开(空白标签页复用否则新开);删除单条 / 清空动作原样保留。
  • i18n 新增词条(zh/en 同步):browser.downloads / privacy / today / yesterday / clearCache 等;「隐私与缓存」两项是建议新增(清缓存 RPC 已有,Cookie 清除需补一个 IPC)。
原型交互:点击节点头可展开/收起(A);hover 根项切换子面板(B);右上 ◐ 切换明暗。
建议 方案 A:信息密度与操作直达性更好,无级联 hover 的命中难题,浮层管理保持单一(一个弹层、一份 freeze 逻辑),实现改动收敛在 BrowserToolbar 一个组件内。
