Git 面板重设计

右栏 360px（默认）· 同一份数据 · 真实 token

三个方案共用同一份仓库数据、同一套语义 token，只在结构上分道：A 走扁平清单（先修布局），B 走单仓聚焦（先修信息密度），C 走勾选式工作流（先修交互）。三案共有的排版修复见页面底部——无论选哪套都该落到实现里。

A

扁平清单

去卡片盒 · 提交框常驻
  1. 提交框常驻：不再随「是否有暂存文件」出现／消失，主操作不再跳动（现状 hasStaged && <CommitBox/>：刚打开面板时压根没有提交框）。
  2. 三层边框 → 一层：repo 头改成吸顶分隔条，去掉 rounded-lg border 卡片盒（面板已有边 + 内边距，卡片是第三层）。
  3. repo 头压成一行：折叠箭头 · repo 名 · 分支 · ↑↓ · 动作。省掉现在只放名字的整行。
  4. 路径双色：文件名 13px + 目录名 11px 弱化——同名文件（多个 GitPanel.tsx）不再歧义。
  5. 单一滚动容器：操作日志从卡片底部移出，收进面板 ⋯，消除「滚动套滚动」。
B

单仓聚焦

仓库页签 · 提交区沉底
  1. 一次一个仓：仓库页签只在 repos > 1 时出现；单仓项目（多数）零多余 chrome。
  2. 当前分支升级为主角：从 10px mono 低对比度药丸 → 12px 内容色可点状态带（它是面板里最重要的信息）。
  3. 提交区沉底 dock：贴近光标／拇指，与聊天输入框同一心智，永远在手边。
  4. 面板级聚合统计：10 变更 · 已暂存 3 · ↑2 ↓1，不必逐卡扫。
  5. 折叠＝真摘要：折叠后仍是分支 + 计数，而不是现在只有名字的空头。
C

工作流三段

勾选取用 · 暂存托盘
  1. 勾选框取代 hover 图标：挑文件成为一等动作，对齐「AI 改完 → 我挑 → 提交」的真实循环（Fork / GitKraken 同款）。
  2. 两段合一：勾选态即暂存态，不再有「已暂存／更改」两个要对照的分区。
  3. 部分暂存可辨：索引里已有内容、工作区又有新改动的文件 = 勾选 + 琥珀点。
  4. 底部托盘实时汇总：已选 N 个文件 · +54 −13，勾一只加一笔，提交前所见即所得。
  5. 筛选框 + 丢弃收进右键：多文件时可定位；破坏性操作离开主路径，降低误触。

三案共性修复（无论选哪套都建议一并落地）

  1. 启用完整字号阶梯：现状 Git 面板只用 base(14) 与 xxs(10) 两级，--rp-fs-md/sm/xs 在整个 ide/ 下只有 2 处引用；且分支菜单与弹窗里有 12 处硬编码 text-[11px] / text-[10px]——它们不跟随设置里的「全局字体大小」。本原型全部走 --rp-fs-*。
  2. 对齐网格：面板 body padding-x 6 ＋ 行 padding-x 6 ＝ 文字起点恒为 12px，组头／repo 头／文件行左边缘严格对齐。现状是三个互不相同的左边缘：组头 8px（body 的 p-2）、文件行 12px（再叠 px-1）、操作日志 10px（px-2.5）——同一张卡里三档缩进，肉眼可见。
  3. 状态色归位：未跟踪／新增改用 --success。现状用 --accent（品牌色，用户可在设置里改成任意颜色）画「新增」，导致同一屏的 diff +（success 绿）与状态字母 A（accent）是两种绿，且改品牌色会让「新增」变色。
  4. ± 计数常驻：现状 group-hover:opacity-0 恰好在你要操作该文件时把数字擦掉。改为 hover 时动作按钮浮上来覆盖，数字不消失。
  5. ± 计数按仓批量取：现状每个文件行各发一次 api.git.diff 再解 patch + 逐行 diff——50 个改动文件＝50 次 git 子进程。建议每仓一次 --numstat／--porcelain=v2。
  6. 操作日志降权：从「每张卡常驻一行表头 + 160px 内滚」改为面板级 ⋯ 或底部状态条——它是排障面，不该常驻占黄金位（且只在内存、切会话即失）。
