# Mcode 终端会话:别在 GUI 和 CLI 之间二选一了

> 一句话:**Mcode**(*my* Code)新增了第五种会话类型「终端会话」——在一个真正的 PTY 里运行**你自己安装**的 AI 编程 CLI(Claude Code / Pi / Codex / Antigravity 四家可选)。Mcode 只当终端宿主,不解析任何协议:CLI 升级即生效,审批、plan 模式、slash 命令全是官方原生 TUI;同时补上了裸终端没有的东西——会话列表、重启后的画面回放与上下文续接、自动命名、文件拖拽、路径点击跳编辑器。

---

## 一、从一个两难说起

如果你同时用过 Claude Code 的终端 CLI 和某个图形界面客户端,多半体会过这种拧巴。

**在终端里跑 CLI**,体验永远最新。CLI 的迭代速度快得惊人,新模型上线当天就能用上,权限审批、plan 模式、slash 命令,全是官方原生交互。但代价是:多项目、多会话全靠 `--resume` 记 ID;想看某个会话烧了多少 token,得去翻 JSONL;报错里那个 `src/foo.ts:42`,你得自己复制路径、切编辑器、Ctrl+G。

**在 GUI 里用**,会话列表、消息搜索、用量统计、文件树、git 面板一应俱全。但 GUI 要解析 CLI 的输出协议,就得捆绑一个自己验证过的 CLI 版本——上游一周更新好几个版本,GUI 的跟进永远慢半拍,你等的新功能排期未知。

这是我在开发 Mcode 过程中被反复问到的问题:**能不能既要 GUI 的管理能力,又跑用户自己装的最新版 CLI?**

最新版 Mcode 的答案是:终端会话。

## 二、Mcode 是什么(30 秒版)

基于 Claude Agent SDK 构建的桌面端 AI 编程 IDE,Electron 三栏布局:左栏项目与会话管理,中间对话流,右栏文件树 / Git / GitHub 面板。

核心理念是「**不重新实现 agent,只做交互界面**」:agent loop 由 Agent SDK 驱动,Mcode 负责会话管理、实时渲染、工具审批和 IDE 能力。除了官方 Claude,还接入了 Pi Coding Agent 和 OpenAI Codex(含自定义 OpenAI 协议端点),工具审批、计划模式、「撤销本轮」文件回滚、定时自动化任务、GitHub PR/Issue 面板,这些增值能力都是 provider 中立的。

而终端会话,恰好是这套理念的一次「反向操作」。

## 三、终端会话:宿主退后,CLI 上场

在 Mcode 里新建一个终端会话,Mcode 会在真正的 PTY 里 spawn 你 PATH 上的 `claude` 命令——**注意,是你自己安装的那个 CLI,不是 Mcode 捆绑的版本**。你昨晚刚升级过的 claude,今天在 Mcode 里就是最新的。

这个设计带来三个直接结果:

1. **升级即生效**。CLI 怎么更新都与 Mcode 无关,不存在「等 GUI 适配」这回事;
2. **零协议耦合**。TTY 是 CLI 对用户承诺向后兼容的接口——内部协议随便改,它自己的 TUI 永远得能用。Mcode 不解析任何东西,自然永远不会被改版打破;
3. **原生体验**。权限审批、plan 模式、`/compact`、模型切换,全是 CLI 自己的界面,交互长什么样完全由官方决定。

会话就排在左栏普通会话旁边(provider 图标 + 终端角标,一眼可辨),切走再切回,输出一个字节都不丢。

## 四、不止 Claude:四家 CLI 随便挑

新建终端会话时的选择菜单:

| CLI | 命令 | 安装管理 |
|---|---|---|
| Claude Code | `claude` | npm 全局包,可在 Mcode 内安装 / 更新 / 卸载 |
| Pi Coding Agent | `pi` | 同上 |
| OpenAI Codex | `codex` | 同上 |
| Antigravity | `agy` | 外部安装,Mcode 提供官网直达 |

设置页新增「终端会话类型」管理区:三家 npm CLI 可以直接在 Mcode 里检查更新、一键安装、卸载。卸载后还有一道复测——如果命令行仍能解析到这个 CLI,说明它来自原生安装器而非 npm,会如实提示你去它自己的安装器里卸,而不是假报成功。哪家不常用还可以单独禁用,菜单里就不再出现。

## 五、重启恢复:画面与上下文,各回各家

终端会话最大的顾虑是:窗口关了、应用重启了,怎么办?PTY 是活进程,一关全没。

Mcode 分两层解决,两层互补。

**第一层:画面回放。** 会话运行期间,终端缓冲区每 3 秒序列化一次快照(内容有变化才写盘)。会话重开时,先把这些「冻结历史」原样回放,再拉起新进程;历史与实时输出之间画一条暗色分隔线,边界清晰。进 claude 之前的 shell 命令、上一次对话滚过的内容,都在。

**第二层:上下文续接。** 这才是关键。首次创建会话时,Mcode 预生成一个 UUID 钉住 CLI 会话;重开时注入 `claude --resume <uuid>`,CLI 从**它自己的**会话文件里恢复完整对话上下文。版本兼容是免费的——那份文件是 CLI 自己的格式,它自己永远认。

四家 CLI 的续接语义各不相同,分别适配:pi 的 `--session-id` 是幂等的「不存在则创建」,首开重开同一条命令;codex 和 agy 没有首开钉子,首次裸启动,由 Mcode 在后台静默「收养」新产生的会话文件,重开时显式 resume。

**收养机制还救过一次真实事故**:实测中,Claude CLI 首次启动恰逢它自己后台自更新,更新重启后的进程丢掉了钉住的会话 ID,整段对话落到了一个随机 ID 的文件里——下次 `--resume` 直接报「会话不存在」。现在 Mcode 会定期对账:钉子对应文件还在,不闻不问;不在,就收养时间与来源都匹配的最新未认领会话文件,把 ID 修正过来。重开一次,上下文照常恢复。

## 六、终端之外,Mcode 补的那些细节

终端会话没有 Mcode 的消息协议可用,以下体验全部靠「物理信号」和终端本体能力实现:

- **「模型处理中」指示**:侧栏的 loading 动画与聊天回合同款。TTY 里没有回合信号,就用量化信号:你按下回车,立即置忙;CLI 处理时 TUI 会持续输出(spinner、流式内容),输出静默 1.5 秒即视为处理结束。
- **文件树拖拽**:把右栏文件树的文件拖进终端会话,`@绝对路径` 直接落进 claude 的输入框——与 GUI 会话里引用文件的写法一致;拖到底部 IDE 终端则是裸路径(shell 里 `@` 是字面字符)。含空格的路径自动加引号。
- **输出内路径可点击**:CLI 报错打出的 `src/foo.ts:42` 变成可点链接,点击在 IDE 编辑器打开并跳到对应行列,支持 `path:行` 和 `path:行:列` 两种写法。还带一层「唯一同名模糊解析」——裸文件名在项目树里全局找,**唯一**命中才跳,有歧义绝不猜。
- **自动命名**:从滚动快照的头部摘录(通常是进 claude 前的 shell 命令和第一个问题)生成会话标题,与 GUI 会话共用同一套开关与模型配置;手动改过名的会话永不覆盖。默认关闭,设置里开启。
- **隐私开关**:终端滚动快照默认落盘(用于重开回放),但终端输出可能包含你刻意打印的敏感内容——设置页可一键关闭持久化。

## 七、实现层面的几个坑(给爱看细节的朋友)

- **为什么回放用「序列化网格」而不是录原始字节流?** TUI 程序靠光标定位和重绘转义序列作画,原始输出流不能安全地掐头去尾——从中间开始播,画面就是坏的。xterm 的 serialize addon 捕获的是**解释后的最终网格**,天然截断安全。
- **回放几何**:快照带绝对光标行号,必须在**与捕获时相同尺寸**的终端里回放,再 reflow 到当前窗格。第一版在默认 80×24 上回放,宽行多折了一遍,光标行号整体前移——表现为 claude 的输入框叠在历史文本中间。
- **字形缺失**:Claude TUI 横幅用 Block Elements(`▐▛██▀▝▜`)作画,JetBrains Mono 不带全这些字形,浏览器回退字体的步进宽度不等于网格宽度,块与块之间出缝。字体链补上 Windows 自带的 Cascadia Mono 后整齐如原生终端;渲染层默认走 WebGL,上下文丢失自动降级 DOM。
- **CJK 宽字符**:路径链接的下划线必须按「单元格坐标」对齐,但一个汉字占 2 个单元格、只算 1 个字符——直接用字符串下标换算,路径前每有一个汉字,下划线就左漂一格。需要一个逐单元格建立的真实映射表才能把下划线画准。

## 八、它不是什么(诚实边界)

终端会话**刻意没有** Mcode 的增值层:没有工具审批卡(审批是 CLI 自己的 TUI)、没有「撤销本轮」文件回滚、没有子代理胶囊、没有 token 用量统计;消息不落库,因此不支持全文搜索;手机端也不显示这类会话。

这不是没做完,而是定位使然:CLI 是黑盒,宿主不解析协议,增值层无从谈起。功能入口的提示文案里,这一点写得明明白白。

所以推荐的使用姿势是:**需要审批把关、rewind、用量统计的重活,用普通 GUI 会话;只想第一时间用上最新版 CLI、顺便借一个好环境,用终端会话。**两者在同一个会话列表里,随时切换。

## 九、写在最后

「GUI 还是 CLI」争论了很多年,但在 AI 编程工具这个具体场景里,它其实是个伪命题:CLI 的价值在于它是官方第一优先级的交互面,GUI 的价值在于管理和可视。

终端会话把两者的边界重新划了一下——**界面的事交给 CLI,Mcode 管会话、管环境、管周边。**

Mcode 是 MIT 协议的独立开源项目(项目地址:发布时补充)。终端会话刚刚落地,如果你也是「CLI 更新强迫症」患者,这大概是目前最省心的用法。欢迎试用与反馈。
