# 桌面端 AI 编程 IDE 该长什么样?我把它改成了监控墙

> 一句话:**Mcode**(*my* Code,MIT 协议的开源桌面 IDE)最近这版只做了一件事——把"一次只盯一个会话"这个默认假设拆掉。会话能拆成四格同屏、侧栏能从屏幕边缘浮出来、提交变成标题栏里的一个数字、第四家 agent 后端(OpenCode)也接上了。

---

先说结论,再讲为什么。

如果你最近的工作是"同时让几个 AI 干活",多半遇到过这个画面:点开会话一,还在跑;切到会话二,在等审批;切到会话三,跑完了,得回头看它改了什么;切到会话四——刚才它改的是哪个文件来着?

这不是你笨,也不是模型慢。这是主流 AI 编程客户端共享的一个前提:**一次只盯一个会话**。模型早就不是瓶颈了,你的注意力才是。

Mcode(*my* Code,一个我维护的 MIT 协议开源桌面 IDE)这一版做的事,就是把这个前提拆掉。

## 会话可以拆开了

最直接的入口:从左栏把会话拖到中间区域,松手落格。也可以右键"分屏打开"。

格子不是写死的 2×2。Mcode 按可用宽度算——每格最小 360px,能横排几列就横排几列,窗口一窄自动收成一列或两列。最多四格,终端会话也能拖进来,和 GUI 会话一视同仁。

底部一条共享输入框,光标在哪个格子,消息就发给哪个会话。这条设计我一开始没当回事,用了两天才发现它是关键:你不用为了给某个 agent 派活而"切过去",点一下格子就派过去了,视线不用搬家。

![四个会话同屏排成网格,底部一条共享输入框](imgs/01-split-view-grid.png)

上图是四个格子同时在跑的状态。底下那条输入框跟着当前聚焦的格子走。

有一个坑我踩过:并发场景下最容易出的错是**配置串了**——A 格子的排队消息用了 B 格子的模型,你以为在用便宜模型跑,账单给你惊喜。Mcode 的做法是每个格子严格按自己会话行的配置发送(模型、思考档、权限各发各的),解析不出来也不会静默借用别的格子的。

还有一层:tabs 模式下,你把会话拖进某个 tab,那个 tab 的内容就地拆开,拖进去的会话**不会**变成新标签。成员是成员,标签是标签。标签条上会挂一个数字徽标,告诉你这一组里有几个会话。

## 侧栏不用再推挤内容了

第二个是交互上的洁癖:侧栏一推开,布局跟着跳,正在看的代码被挤走,回来还得重新找刚才读到哪。

但很多时候你并不是想"打开并停留",只是**瞄一眼**。瞄一眼的代价不该是一次布局地震。

现在的交互是:侧栏关着的时候,鼠标贴到屏幕边缘停零点一几秒,面板像抽屉一样浮出来,浮在内容**之上**,不挤压任何东西;鼠标移开,自己滑回去。左边是会话列表,右边是文件树和 git。

![右侧文件树从屏幕边缘浮出,盖在聊天内容之上,布局没有位移](imgs/02-edge-peek-right.png)

上图右边那块是浮出来的文件树,底下的聊天流一动没动。

有个细节我自己挺喜欢:右栏关着的时候,如果我在聊天里点开一个文件,文件树会自己滑出来展示它,几秒没人理会就默默收回去。它像个有分寸的助手,而不是需要你随手关门的柜子。

顺带一个改动:**agent 驱动内置浏览器的时候,右栏图标只亮一个呼吸的圆点**,告诉你"我去那儿了",不再强行把你从正在看的文件面板切走。以前这种自动跳转最烦人。

## 提交这件事,摩擦力必须趋近于零

第三个是 git。

以前提交的链路是:切到 git 面板 → 找到仓库 → stage → 憋 commit message → 提交。别小看这条链,摩擦力够大的时候,人就是会"等会儿再说"。而 AI 时代改动堆积的速度远快过我提交的速度,一个下午下来变更列表里躺着一百多个文件、分属四条不相干的任务线,到提交时已经分不清哪块改动属于哪个会话,只能靠 git diff 考古。

现在它变成了标题栏上的一个数字:分支名旁边常驻变更计数,新增是绿的、删除是红的、其余是灰的,一眼看见。

![标题栏分支名旁的变更计数徽标,点开后是提交弹层](imgs/03-toolbar-git-commit.png)

点开是一个弹层:多仓库项目可以切仓库;提交信息由 AI 基于这次的 diff 起草;"提交"和"提交并推送"两个按钮,作用于全部改动(含未跟踪文件),提交前自动全部暂存。看完觉得行,三秒钟落袋为安。

这里有个只有真跑过才知道的细节:模型起草的 commit message 会带上署名尾注(`Co-Authored-By: Claude Code …` 或者 `🤖 Generated with …`)。因为提交信息的生成路径把系统提示词整个换掉了,模型按训练惯性还是会加尾注,光在提示词里禁止没用。所以后面还有一道**确定性的清理**:把这些行剥掉,顺手修好删除后留下的空行。但人类合著会保留——真名叫 John Claude、邮箱是自己的,那行不动。

大改动当然还是要进 git 面板逐文件审。这个入口解决的是高频小提交,别拿它当审阅工具。

## 接了第四家 agent 后端:OpenCode

第五家 CLI 进终端会话之前,Mcode 的 GUI 后端只有三家(Claude Code、Pi、Codex)。现在 OpenCode 也进来了,而且是**双形态**。

作为 GUI 会话:审批卡、用量统计、子代理转录全齐。OpenCode v2 是 client-server 架构,Mcode 自己 spawn 一个私有 server 接管,权限判定放在宿主侧的桥里解释——所有询问走一遍宿主自己的守卫(项目边界、bash 写目标、隔离档读界),再决定放行还是弹审批卡。应答只用"本次"或"拒绝",**永远不用"永久允许"**:永久允许是服务端的模式白名单,一旦用它,后续同类调用就绕开了宿主守卫,那道围栏等于白设。

作为终端会话:跑的是你自己 npm 装的 opencode,和你终端里那个共享登录态;Zen 的免费模型不登录也能直接用。

![设置页里的 OpenCode 面板与模型列表](imgs/04-opencode-models.png)

终端会话这一块现在支持五家 CLI:claude、pi、codex、opencode、agy(Antigravity)。设置页里能直接查更新、装、卸——卸载后还会复测一次,如果命令行仍能解析到这个 CLI,说明它来自原生安装器而不是 npm,会如实提示你去它自己的安装器里卸,而不是假报成功。哪家不常用可以单独禁用,菜单里就不出现。

## 还有两个小改动

**会话可以分叉了。** 以前想试另一条路线,只能编辑重发最后一条消息;现在可以从任意一条消息分叉出一个独立会话——转录按 prompt 对齐切尾复制过去,原会话和模型的记忆都不受影响,还能顺手勾一个 git worktree 让它在独立检出里跑,别把主目录改了。

![从某条消息分叉出新会话的对话框](imgs/05-fork-dialog.png)

另外还有一批渲染上的收拾:媒体从一张张铺开改成可折叠的抽屉(标题带计数,能"预览全部"),PDF 用 pdfjs 自己画(不用另开浏览器),Mermaid 图直接渲染,工具跑完不再给个绿勾(活跃回合里一排绿勾纯属噪音)。

## 谁该用,谁不该

**该用:**

- 同时要跑两三个 agent 的人——这是这版改动的主受众;
- 愿意折腾端点的人:OpenAI 协议桥、自定义请求头、模型级思考档声明都在;
- 想让 agent 用真实 Chrome 登录态去点东西的人(装个浏览器扩展就行);
- 想在手机上看着电脑跑的:Mcode 有局域网配对和 SSH 中继。

**不该:**

- 只跑一个 agent、一个项目——那样的话,终端加编辑器真的够了,Mcode 反而是负担;
- 想要团队协作、看板、issue 流转——这它不是。虽然有 GitHub PR/Issue 面板,能提 PR、能评论、能把 PR 变成 issue,但它不是 Linear。

**不确定的地方我也说清楚:**

- 屏幕小于 27 寸时,四格会挤到看不清文字。宽度自适应会自动降到两格,但这时候开两个窗口可能更舒服;
- OpenCode 那套是刚接的,它的 SDK 类型比 CLI 慢半拍,事件词表随 CLI 升级漂过好几次。我用探针脚本对着真实 CLI 校准,还留了两个探针脚本方便以后复测,但这块的维护成本是实打实的;
- 这仍是 alpha,Bug 会多。开了 issue 我基本都看。

## 收尾

并行不是多开几个窗口,是把"轮询"这个动作从人身上拿走。

Mcode 是我用业余时间维护的开源项目(MIT)。上面这些改动都已经在最新版里。如果你最近也在让 AI 并行干活,建议先试试把两个会话拖进同一屏——那个"不用再切来切去"的感觉,一旦有了就回不去了。

GitHub 搜 **mcode**,或者应用内直接更新。
