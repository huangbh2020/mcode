# 模型配置页重设计(布局与排版)

> 范围:`CustomModelsPanel`(设置 → AI 能力 → 模型配置)一页。**只出设计,未改任何代码。**
> 主题兼容是硬约束:classic 浅/深、手绘纸面、深色牛皮纸、用户自定义界面字体(见 §7)。
> 配套全局设置改版已确立的设计系统见 [`docs/settings-redesign.md`](settings-redesign.md);本文只提该页,不重开全站议题。

---

## 0 结论摘要

一句话:**把"标签在上、控件满宽"的竖向堆叠改成"标签列 + 控件列"的行式表单,把三轴导航压到两轴,给详情列补上它缺失的身份头与常驻动作条。**

具体五个动作:

1. **排版换范式**:原子字段走 `标签列(160px) | 控件列(≤640px)` 的同一行,不再各占一整行;
2. **压掉一层导航**:Claude/Codex/Pi 家族页签搬进 `PanelHeader` 的 action 槽(与页面标题同一带),页面少一整条横栏;
3. **给详情列一个头**:供应商名 + 元信息 + 测试连接/删除,不再"落地即一片输入框";
4. **动作条常驻底部**:保存/取消/删除不再压在长表单末尾;
5. **模型列表变真表格**:统一列模板 + 表头,替掉三套手写行模板与裸文字「1M」开关。

主题侧的两条硬结论:**同色父层上的 `bg-surface/40` 合成为不可见(现列表/详情的填充是空的,层级全靠描边撑)**;**手绘主题下描边会加粗到 1.5px 墨线,所以嵌套描边必须收敛到两层**(详见 §7)。

## 2 设计目标与约束

**目标**:一屏内(1440×900)看清"我在编谁 + 有哪些字段 + 怎么保存";表单不再需要为了保存而滚到底;四套主题下同一份代码都成立。

**约束**:

- 只动这一页 + 允许新增本页私有原语;**不改** `SettingRow`/`SettingsSection`/`PanelHeader` 的既有语义(16 个页面在用);
- 颜色一律走语义 token,`html.sketch` 的选择器不许散落到本页(集中在 `styles.css` 的 Sketch 区块);
- 尺寸一律用 em 派生自 `--right-panel-font-size`(14px classic / **15px sketch**),px 只允许出现在结构尺寸(轨宽、列宽);
- 不新增功能语义:不引入"启用/默认供应商"(现在没有这个概念),选中 = 正在编辑。

### 3.2 三条几何规则

| 规则 | 值 | 理由 |
|---|---|---|
| 面板宽度上限 | **1180px**(原 1024) | 内容区在 1440 窗口是 1152;老值留下 128px 双侧空白,同时压窄了模型表 |
| 供应商轨 | **232px**(原 210)+ `gap-4` | 副行「3 个模型 · 未配置 Key」在 0.7857em 下约 150px;210 会把副行压成省略号 |
| 详情列 | 剩余(≈930px) | 表单栅格 `160px + ≤640px`,余量作右侧留白——给表单一个阅读宽度,避免 4K 下输入框拉到 900px |

**保留"双列各自滚动"而不是改成一容器滚动**:主从页的内部滚动是正确的模型(与 Skills 一致),`PanelHeader` 在这一页不吸顶也无害(它本来就永远可见)。**不采纳**设置改版方案 B 的"再加一条本页索引列"——本页的供应商列表**就是**索引,再加一列会把它挤到 500px 以下。

### 3.3 窄屏降级(容器查询,断在详情列上而非视口)

| 详情列宽 | 形态 |
|---|---|
| ≥ 560px | 行式:`标签列 160px | 控件列 minmax(0,640px)` |
| < 560px | 行降级为块:标签在上、控件占满(即"块变体"),标签列消失 |
| 内容区 < 720px | 双列塌成单列:供应商轨收成一个「供应商 ▾」下拉(整宽 md),详情列占满 |

用 `@container` 而不是视口断点:窗口宽度不等于详情列宽度(左导航固定 240、面板居中、轨宽也会变),视口断点必然算错。

## 4 排版尺度

**只使用已有的 `--rp-fs-*` 令牌层级**(`styles.css:440-443`),不为本页新增半像素档:

| 角色 | 字号 | 字重 | 颜色 | 令牌 |
|---|---|---|---|---|
| 页面标题(面板头,共用) | 0.9286em | 600 | `content` | `--rp-fs-md` |
| 家族页签 | 0.8571em | 500 | `content` / `content-muted` | `--rp-fs-sm` |
| 详情头 · 供应商名 | 1em | 600 | `content` | 基准 |
| 分组标题(端点/认证/模型) | 0.9286em | 600 | `content` | `--rp-fs-md` |
| 行标签 | 0.8571em | 500 | `content-muted` | `--rp-fs-sm` |
| 控件值(输入框/下拉内的字) | 1em | 400 | `content` | 基准 |
| 行描述、右侧说明、表头、眉标 | 0.7857em | 500 / 400 | `content-subtle` | `--rp-fs-xs` |
| 元信息(列表副行、详情头副行、计数、耗时) | 0.7857em | 500 + `tabular-nums` | `content-subtle` | `--rp-fs-xs` |
| 列表项主行 | 0.9286em | 500 | `content` | `--rp-fs-md` |

三条规则:

1. **不再使用 0.7143em 承载可读文案**(现在 10px 的副行、计数、列表眉标)。0.7143em 只留给纯装饰;手绘基准 15px 下它=10.7px,楷体依然发虚,而 0.7857em=11.8px 可读。
2. **提示文字从 0.6428em(9px)提到 0.7857em(11px)**。这是本页在纸面/牛皮纸主题下最实际的可用性修复——手绘字体小字号本来就虚,9.6px 基本读不出。提示与描述同级同色即可,不必再小。
3. **层级靠"字号 × 字重 × 颜色"三轴,不靠半像素**:文档层曾提过 0.821em/0.964em 两个档,这里刻意收敛回既有令牌(元信息与描述同字号,靠字重 + `tabular-nums` + 颜色区分)。少一档就少一处漂移。

`行高`:控件 30px(`Input`/`Select` 现为 `px-2.5 py-1.5 text-xs` ≈ 30px);行垂直留白 `py-2.5`;分组间距 `mt-4 + pt-4`;发丝线 `divide-y divide-edge`。

**控件文字从 12px 提到 14/15px**:`Input` 原语强制 `text-xs` + `font-mono`(`input.tsx:26`),使"名称"比它的标签只大 1px 且是等宽。本页所有控件经 `className` 覆盖( tailwind-merge 会正确顶掉 `text-xs`/`font-mono`):

- **人读字段**(名称、Provider 名称、显示名)→ `font-sans text-[1em]`;
- **机器标识**(Base URL、模型 ID、Provider ID、请求头名/值、maxTokens)→ `font-mono text-[1em]`;
- 顺带把 `Input` 的 `rounded`(4px)统一到 `rounded-md`(6px),与 `Select` 对齐。

## 5 组件规格

### 5.1 行(本页私有 `ProviderField`,三种变体)

| 变体 | 栅格 | 用于 |
|---|---|---|
| `row`(默认) | `grid-cols-[minmax(112px,160px)_minmax(0,640px)] items-center gap-x-4 py-2.5` | 单行值:API 格式、名称、Base URL、Token、认证方式、超时、开关行 |
| `block` | 标签行(标签 + 可选行内动作)→ 内容整宽 | 模型表、自定义请求头 repeater |
| `trailing` | 行内:控件 + 右侧动作簇(`flex items-center gap-1`) | 带眼睛图标的密钥、带测试/删除图标的模型行 |

要点:

- **右侧空余处当提示槽**:控件列上限 640px,剩下的横向空间在 `row` 变体里用于放右侧说明(`仅支持 /v1/responses`、`关闭=200k`)。提示不再占第二行,于是**每一行都是固定 50px(30px 控件 + 2×10px 留白),与有没有提示无关**;带提示的字段(现状 78px)收成一行,Claude 表单主体约矮 25%,且高度可预测——这比"矮多少"更重要。没有提示的行留空即可(不要居中、不要右对齐文字,保持一条连续的左边缘)。
- 标签列固定 160px 上限、112px 下限:足够「Base URL」「认证方式」,也容忍窄屏收缩。
- 开关 `Switch` 在 `trailing` 里右对齐到控件列右缘,不单独占一列——与 `SettingRow` 既有约定一致(下拉/输入左对齐填满、开关右对齐)。

### 5.2 模型表(替掉三套手写行)

```
模型 ID                      最大输出   1M    操作(sr-only)
[claude-sonnet-4-5      ]     —       [●]   [⌁] [🗑]
```

- 列模板:`grid-cols-[minmax(0,1fr)_96px_72px_88px] items-center gap-2 py-2`,`96/72/88` 三列按家族显隐(Pi 有最大输出与展开键,Claude 有测试键,Codex 只有删除)。
- 表头行:同列模板 + `0.7857em/600 content-subtle`,`tracking-wide`;「操作」用 `sr-only`(视觉噪音为零但读屏可达)。
- **`1M` 的表头承担解释责任**:单元格只放开关 + `title`/`aria-label`(复用既有的 `supports1mLabel`),不再在每行重复小字。
- 行分隔靠 `divide-y`(发丝线),**不给每行加边框盒子**——这是手绘主题下最容易失控的一处(见 §7)。
- 空态:虚线框 + 「添加第一个模型」动作(复用 §5.5)。
- 「添加模型」按钮放在**分组标题行右侧**,不再跟在最后一行后面。
- 可选(非本期):`dnd-kit` 行拖拽排序(顺序即模型选择器顺序)。

### 5.3 供应商列表(轨)

- 容器:`bg-surface-muted/70` + `rounded-lg`,**不描边**(用真实填充表达"凹槽";`bg-surface/40` 那套等于没有填充,见 §1.2)。
- 项:`rounded-sm` + `px-2.5 py-2`,主行 `0.9286em/500 content`,副行 `0.7857em content-subtle`;选中态 `bg-surface-hover` + 左侧 `w-0.5 h-4 rounded-full bg-accent` 竖条(保留既有形态)。
- **副行补一个警告点**:`无模型` / `未配置 Key` / `Base URL 为空` 这类"打开才发现"的坏配置,在副行前置 6px `bg-warning` 圆点(带 `title`)。数据全在现有 state 里,不需要新接口。
- 空态:`emptyProviders` 升级为虚线框 + 图标 + 一句"下一步"(「还没有供应商配置。点下方新建一个,或在应用内先选一个模型」),配 §5.5 的 `EmptyState`。
- 草稿态:保留现有虚线 + `accent` 的"新建 …"行,但补齐右侧的同款竖条与 `px/py`(现在它与真实项的内边距不一致)。
- 过滤框:仅当条目 > 8 时显示(供应商一般 <10,不预置无用的输入框)。

### 5.4 详情头(新增)

```
官方中转  [OpenAI 经翻译]                       [测试连接] [删除]
Bearer · 3 个模型 · Key 已配置 · 上次测试 812ms
```

- 左:名称(`1em/600`)+ 协议徽标(仅 `openai` 协议显示,复用 Badge 规格)+ 副行元信息(`0.7857em content-subtle`,`tabular-nums`)。
- 右:动作槽。**测试连接只在有可测模型时可用**(现在仅 Claude 有该能力;Codex/Pi 接入测试是独立议题,列 §11 非本期,本设计只要求位置预留)。
- 脏标记:未保存时名称后跟 `●` + 副行追加「未保存」,与动作条联动(§6.1)。
- 新建草稿态:标题显示「新建 Claude 端点」等既有词条,隐藏删除。

### 5.5 空态与折叠(各只留一种写法)

- `EmptyState`:虚线框 + 32px 图标块 + 标题 + 一句说明 + 可选动作。现在**模型列表已经是虚线框**(`:1129/:1315/:1562`),供应商列表与详情是纯文字(`:936` 纯文字、`:1168` 居中圆标+文字)——统一到一种,三处都换成 `EmptyState` + 一个"下一步"动作。手绘主题下虚线框本就是该主题的惯用形态(终端宿主、代码块都转虚线),这里天然同构。
- `Disclosure`(高级选项 / Pi 单模型展开共用):整宽按钮行 = chevron + 标题 + 右侧摘要(`超时 · 禁用遥测 · 自定义请求头`)、上缘发丝线;展开区是**缩进子面板**——左侧 2px 的 `bg-edge` 竖导轨 + 同款行栅格,**不加第二个边框盒子**。

### 5.6 动作条(常驻)

- 位置:详情列底缘 `shrink-0`,上缘发丝线 + `bg-surface`,`px-3 py-2.5`。
- 内容:`删除`(仅编辑态,`variant="danger"` 幽灵态,与右侧主/次动作之间用 spacer 隔开)→ 右 `取消`(ghost,`size="md"`)+ `保存`(primary,`size="md"`)。
- 按钮从 `sm`(24px/11px)提到 `md`(32px/12px):与 30px 的输入框同高,动作条不再像"贴在表单下的小零件"。
- 测试结果徽标(`连接成功 · 812ms` / 失败原因)从 `FormActions` 的散落 span 收到动作条左侧固定槽,失败进 `danger`,成功进 `accent`。

## 6 交互与状态

### 6.1 未保存状态(现在完全没有)

- 脏标记 = 表单值 vs 打开时的快照深比较(本页表单都是平铺标量与数组,不需要额外的引用技巧)。

- `⌘S / Ctrl+S` 提交(挂在本页容器上,不抢全局)。

### 6.2 错误与校验

- 字段级:统一为"标签列下方/控件右侧"的 `danger` 小字(不带框,不用第三种样式);控件加 `error` 态(`Input` 已支持 `error` prop)。

### 7.2 手绘主题的四条硬约束(改这里前必读)

1. **描边深度封顶两层**。`html.sketch .border` 会把 1px 加粗成 1.5px 墨线(`styles.css:2167`),所以同一竖列里"盒子套盒子"会迅速变成格子纸。本页的约定:容器最多一层描边(详情列),里面**全部**用发丝线(`divide-y`/`border-t`)与填充分层;模型行、高级选项、Pi 展开区一律不给独立边框。现状最坏处是三层:详情盒 → 高级盒或模型行盒 → 输入框,一个字段竖列里三条墨线并排。
2. **圆角同心,不叠抖**。外层 `--sk-r-md` 里不要再放一个 `--sk-r-sm` 的**整框**;要放就放无框的填充块。小尺寸容器(列表项、表格行)用 `rounded-sm`(2px,**不在手绘映射表内**)保持锐利——手绘主题已有同类取舍先例(上下文环/头像/状态点刻意保持正圆,见 `styles.css:2017`),密集等高的行同理:每行四个角都在抖会读出参差,行的边界交给填充表达。
3. **阴影不承担层级**。`html.sketch .shadow-sm` 被映成硬偏移阴影(`styles.css:2155`),把阴影当"卡片浮起"用会在纸面上糊成一团。容器层级只允许填充 + 发丝线;阴影留给浮层(弹窗/下拉/提示),那是浮层该有的语义。
4. **可读字号下限 0.7857em**。手写字体小字号发虚,0.6428em(14px 基准下 9px;手绘基准 15px 下 9.6px)不可读。提示/描述/表头/元信息统一 0.7857em(11px / 手绘下 11.8px)。

### 7.3 自定义界面字体(`ui.uiFontFamily`)与等宽面

- sans 面自动跟随用户字体;手绘下由 `html.sketch body, #root` 覆盖到手写栈——本页不写任何字体相关的 sketch 选择器,也不必写(尺寸与字重照常)。
- **等宽面必须显式 `font-mono`**:模型 ID、Base URL、Provider ID、请求头名/值、maxTokens。这些是"代码/标识"面,手绘红线是"代码不手绘"(UA 对 `pre/code` 有直选 mono,但 `input` 没有),而 `Input` 原语的默认 mono 又恰恰被我们用来区分人读字段 —— 所以**两处都要显式声明**,不能靠省略。
- 用户改字号(设置 → 外观)会改 `--right-panel-font-size`,本页全部尺寸随之缩放,不需要任何额外处理(这是 §4 规则 3 的收益)。

## 7.5 实测补充(2026-09-12,做 `prototypes/settings-pages-redesign.html` 时量到的)

这一节是照 §7 的规则画稿子时用 headless Chromium 实测出来的三件事,其中两条修正/加固了 §7.2 的规则。

**① 手绘的「1.5px 墨线」在 1x 屏上视觉等于 1px。** `html.sketch .border{border-width:1.5px}`(`styles.css:2167`)声明没错,但 **Chromium 把 `border-width` 向下取整到整数 CSS px**——实测 1.5px 的计算值读回 `1px`、2.5px 读回 `2px`,dsf=1/2/3 读数一致(连新建的 `border:1.5px solid` 元素也一样)。也就是说这条规则在计算值层面**看不到差别**,`getComputedStyle` 也验证不了它(想验证只能读 CSSOM 的声明值)。推论:**描边粗细不是一个可用的层级变量**——§7.2 规则 1「描边深度封顶两层」不只是为了手绘的观感,而是因为加粗这条路本来就走不通。Retina 屏上的实际绘制像素值得在真机再确认一次(如果确实也不生效,这条规则可以删掉,省一次无意义的风格分支)。

**② 纸面主题的「描述/元信息」层对比度不达标。** 四套主题下量得行标题 / 描述(元信息)对卡片底的对比度:

| 主题 | 标题 | 描述/元信息 |
|---|---|---|
| 浅色 · 经典 | 19.90:1 | 4.83:1 |
| 深色 · 经典 | 13.77:1 | 8.86:1 |
| 浅色 · 纸面 | 11.78:1 | **3.58:1** ⚠ |
| 深色 · 牛皮纸 | 10.34:1 | 4.93:1 |

纸面这一档低于 WCAG AA 的 4.5:1,而它承载的恰恰是字号最小的那层(提示、表头、元信息)。

- 深色经典早就为设置面板做过提亮(`styles.css:333` 的 `.dark:not(.sketch) .settings-root`),**纸面没有对应补偿**;
- 该提亮规则显式排除了 sketch,理由是「kraft 暖底上冷灰会冷暖打架」——这个理由对牛皮纸成立,但**纸面(浅色手绘)不该被这条排除连带**,它的底是浅暖纸,不存在冷暖冲突;
- **建议的修法(一行)**:`html.sketch:not(.dark) .settings-root{--content-subtle:109 100 86}`(即复用 content-muted 的值),实测对比度 3.58 → **5.58:1**。若不想动令牌,退一步是把 desc/提示层直接改用 `text-content-muted`。

本文所有规格都按"这一层要能读"来定,所以这条不影响 §4 的字号决策,反而印证了 §4 规则 2(提示从 0.6428em 提到 0.7857em)——小字号 + 低对比度同时踩,那一层就彻底读不出来了。

**③ 开关的「已开启 / 已关闭」并不在正文里。** `NotificationsPanel` 只把 `settings.on` / `settings.off` 传给 `Switch` 的 `label`,而该 prop 仅落到 `aria-label` 与原生 `title`(见 `components/ui/switch.tsx`);正文里没有任何状态词。所以 `docs/settings-redesign.md` §2.4「开关旁的状态词是噪音,应删除」在今天的代码上**不成立**——没有这个动作可做。(该文档其余几条本次逐条核对属实:插件/MCP/LSP 的空态与徽标确实各写一遍。)
