## 2 现状问题(按"改不改得动"排序)

### 2.1 两套骨架并存(结构性问题)

- 表单类页面用 `section.max-w-3xl.space-y-4`,靠**中间内容区**滚动(`SettingsPage.tsx:220`);
- 模型配置 / Skills 用 `div.mx-auto.flex.h-full.max-w-5xl.min-h-0.flex-col`,**自己不滚动**,左右两栏各自内部滚动。

后果:页面宽度在 768px ↔ 1024px 之间跳;同一个滚轮手势在不同页面上滚的是不同的东西;`PanelHeader` 的 `sticky` 在有内部滚动的页面里等于失效。**这是最值得先统一的一处。**

### 2.2 分组层级三层的代价

现在是「面板标题(`PanelHeader`)→ 卡外分组小标题(`SettingsSection` 的 `h3` + desc)→ 卡片 → 设置行(`SettingRow`)」。
卡外标题与卡片边框之间有一段真空(`space-y-1.5` + 卡片自身 padding),同样的信息多占约 30px 垂直空间。`PanelHeader` 的注释里已经记着"不要再加页面级描述,否则第一张卡被推到折叠线以下"——层级本身在吃预算。

### 2.3 原语各写了一遍

| 语义 | 现有实现 |
|------|----------|
| 空态 | 虚线框(终端命令、插件市场)/ 纯文字(模型配置、MCP)/ `Card` 内文字(语音) |
| 折叠 | 高级选项(`CustomModelsPanel` 自写 chevron)/ LSP 语言行 / 运行时行 / 插件行 —— **四套** |
| 状态徽标 | 插件的 `chip` / MCP 的 `KindBadge` / LSP+运行的 `StatusBadge` —— **三套**,字号与内边距都不同 |
| 破坏性确认 | `ConfirmDialog`(插件/Skills/MCP/模型配置/浏览器)+ **原生 `window.confirm`**(运行时卸载、LSP 卸载、语音模型删除) |
| 保存语义 | 即改即生效(开关/下拉/色板)与显式保存按钮(终端 Shell、浏览器目录、LSP 覆盖、provider 表单)混用,行内提示有的有(`已保存。…`)有的没有 |

### 2.4 开关旁的状态词

`NotificationsPanel`、`VoicePanel`、`AppearancePanel` 里每个开关右边跟一句「已开启 / 已关闭」。开关本身就是状态,该文字只贡献噪音——真正需要说明的是"关闭后会发生什么",而那属于描述。

### 2.5 变更不可追溯

17 个页面、上百个设置项,用户没有任何办法知道**哪些项被改过**、也就不敢点"恢复默认"(而快捷键/手势页恰恰各有一个"恢复全部默认"按钮)。这是设置面板最常见的信任问题。

### 2.6 找不到设置

导航是 17 项、5 个**不可点击**的分组眉标(纯装饰),平铺 240px 宽。找「语音识别模型目录」需要先猜它在"输入与提醒 → 语音"。全应用唯一能做设置检索的地方不存在。

### 2.7 宽窗口浪费

`max-w-3xl`(768px)在 1440 窗口里,内容只占 53%,左导航 240px 之外的两侧全是空白;而同一时刻语音/终端/MCP 这些页面又需要纵向滚很久。

## 3 三个方案

三个方案**共用同一套设计系统**(第 4 节),差异只在:导航形态、是否有"本页索引"、分组呈现方式、内容宽度策略。稿子顶部切换即可逐页对比;`1`/`2`/`3` 切方案,`[`/`]` 翻页,`#c/plugins` 这样的深链可直接分享。

### 方案 A · 精修卡片流(改动最小)

保持现有信息架构,把细节做对:

1. **分组从「卡外小标题 + 卡片」并为「卡片自带头部」**(图标 + 标题 + 描述 + 右侧元信息),层级三层降到两层;
2. 一个滚动容器 + 一个固定页头,不再依赖 `sticky` + `mt-5` 的占位技巧;
3. **行模板统一**:标签列 + 控件列,同一张卡内控件共线;长描述不再把控件挤到第二行;
4. **开关去掉「已开启/已关闭」**;
5. **改动可追溯**:被改过的行标一个点,hover 出现「恢复默认」;页头显示「本页已改 n 项」+「恢复本页默认」;导航项上也挂计数;

> 代价:密度基本不变;导航仍需靠记忆;宽窗口下仍有空白。

### 方案 B · 双栏工作台(密度最高)

导航(212px)+ **本页索引**(216px)+ 正文:

1. 索引列列出"这一页有哪些分组、各改了几项、各有多少条设置",点击跳转,长页面不再靠滚动找定位;
2. **主从页面的列表搬进索引列**:模型配置现在是「210px 列表 + 详情」,1440 窗口下表单只剩 600 多 px;合并后详情表单拿回全部宽度(见稿子 `#b/custom-models` vs `#a/custom-models`);
3. **分组头改成 sticky 行**(标题 + 说明同行),不再画卡片边框,行间只留发丝线 —— 同样内容高度减少约 25%,观感更接近 IDE/工具;
4. 窄窗口(<1200px)导航降级为图标轨、索引列收起。

> 代价:两条侧栏合计约 430px;只有一两个分组的页面(通知、浏览器)索引列信息量偏低。

### 方案 C · 自适应网格 + 全局搜索(易用性最强)

1. 导航收成 **58px 图标轨**(可固定展开);
2. 正文变成 **两列卡片网格**:短分组并排(字号/缓存/登录状态),长内容(热力图、插件列表、provider 表单、SKILL 编辑器、MCP 各分组)整行跨列。一屏信息量约翻倍;
3. 顶部 **常驻设置搜索**:输入即过滤 —— 不命中的分组与行直接收起,导航同步过滤,`⌘K` 聚焦。已实测:输入「归档」时导航从 17 项收敛到 1 项、当前页 16 个可命中元素里收起 10 个、9 处高亮;
4. 窄窗口自动回落到单列(等于方案 A 的形态,可直接拖窄窗口验证)。

> 代价:改动摇杆最大;搜索要真正好用需要给每条设置补**关键词**字段(现在 i18n 只有标题与描述);极宽窗口要避免卡片被拉得过宽(已用 `max-width` 兜住)。

### 共同要做的事(与布局无关)

- 一套原语替代按页手写(见第 4 节);
- **破坏性操作统一确认弹窗**,`window.confirm` 全部下线,弹窗里写清后果(如"卸载运行时会让该 Agent 不可用");
- **保存语义显式**:即改即生效的给一次淡淡的「已保存」,多字段表单才用底部动作条;
- 列表页(快捷键/手势/插件/MCP)在页头同一位置提供过滤框;插件搜索同时匹配组件名;
- 状态色只有五档(中性/强调/警告/危险/信息)× 实心与描边两态;
- 键盘可达:行可聚焦、开关空格、折叠 Enter、Esc 退出设置。

## 4 设计系统(三方案共用,实现时按此写)

### 4.1 尺度

| 项 | 值 |
|----|-----|
| 基准字号 | `--right-panel-font-size`(默认 14px),所有尺寸用 em 派生 |
| 页面标题 / 卡片标题 / 行标题 / 描述 / 元信息 | 1.107em·650 / .964em·600 / .929em·500 / .857em·400 / .821em·500 |
| 行内间距(舒适 / 紧凑) | `py 12px / 7px`;卡片内边距 14px / 10px;分组间距 14px / 8px |
| 页面左右留白 | 24px(紧凑 20px) |
| 圆角 | 卡片 12px、控件 8px、胶囊 999px |
| 表单阅读宽度 | 表单页 820px;主从页/网格 1180px |
| 控件列宽 | 表单页 240px;网格页 220px;全宽卡 260px |
| 阴影 | 卡片 `0 1px 2px /4%`;仅弹层用大阴影 |

### 4.2 原语(每个只允许一种写法)

| 原语 | 规格 |
|------|------|
| `SettingsSection` | 卡片 = 头部(图标 26px 圆角 8px + 标题 + 描述 + 右侧元信息)+ 行容器(`divide-y` 发丝线)+ 可选脚注(`snote`)。方案 B 换成 sticky 组头 + 无边框面板 |
| `SettingRow` | `grid: minmax(0,1fr) auto`;标签列(标题 / 描述 / 可选次行),控件列固定宽;`stack` 变体用于路径、色板、多行文本、按钮组 |
| 变更标记 | 标题前 6px accent 点(仅当值 ≠ 默认)+ hover/常驻淡显的「恢复默认」图标按钮;分组头与页头显示聚合计数 |
| `Switch` | 34×20,开 = accent;`sm` 30×18;**不带状态文字** |
| `Select` | 30px,右侧 chevron,超长省略;`sm` 26px |
| `PathField` | mono 值框(可截断)+ 动作按钮(选择目录…/保存/恢复默认)+ 行内「已保存」提示 |
| `ListEditor` | 卡内区块:标题 + 计数徽标 + 「添加」;条目 = 名称 + mono 命令 + hover 操作簇;空态用虚线框 |
| `Disclosure` | `chevron + 摘要行 + 内嵌面板`;展开时容器 `data-open="true"`,面板给浅底 + 上分割线(取代四套自写折叠) |
| `Badge` | 高 18px,11px·600;五色 × 实心/描边;状态类可带 5px 圆点 |
| `EmptyState` | 虚线框 + 32px 图标块 + 标题 + 一行说明 + 可选动作;全站唯一空态写法 |
| `ConfirmDialog` | 破坏性操作统一入口;danger 主按钮;不可逆且影响大的(卸载运行时)要求输入名称确认 |
| `SearchField` | 28–32px,左侧图标,右侧 `⌘K` 键帽;匹配范围 = 标题 + 描述 +(建议新增)关键词 |

### 4.3 交互规则

- **即改即生效**(开关/下拉/色板/步进):不出现保存按钮,行内出现一次「✓ 已保存」并淡出;
- **显式保存**(provider 表单、SKILL 正文、Shell 路径、路径覆盖):底部动作条「左危险 / 右次要 + 主」,离开未保存时提示;
- **过滤**:页头过滤框只作用于当前页;导航搜索作用于全站,两者共用同一匹配函数;
- **空态必须给出下一步**(「还没有安装插件。切到插件市场浏览,或用右上角安装」比「暂无数据」有用)。

## 6 落地路径建议

不建议三选一后一步到位,分两步风险与收益最可控:

1. **第一步(系统层,1–2 天)**:原语组件 + 变更标记与恢复默认 + 页头结构 + 统一确认弹窗 + 保存语义。
   不改变信息架构,做完这一步 **方案 A 已达成约 80%**;
2. **第二步(按页面推进)**:先做 B 的导航 + 本页索引(对模型配置/Skills/MCP/插件收益最大,能顺势删掉一层重复列表),再按 C 给短分组铺网格与全局搜索。两者不冲突:B 的索引列与 C 的网格可以共存;
3. **暂不做**:不重构 17 个页面的分组归属,也先不改导航文案。等设置搜索上线后观察哪些页面几乎无人进入,再考虑合并。

工作量粗估(单方案全量落地,不含新功能如"测试通知"):第一步 1–2 天;A 的页面铺开 +1 天;B 或 C 的页面铺开 +2 天;搜索关键词字段补充(17 页 × 约 120 项)约 0.5 天。

## 7 待你决策

1. **选哪个方向**(或"B 的导航 + C 的网格"这类组合);
2. **是否接受即改即生效的保存语义**(会去掉终端/浏览器/LSP 上的"保存"按钮,改为行内"已保存"提示);
3. **是否做全站设置搜索**(需要给设置项补关键词,约 0.5 天;这是"找不到设置"的唯一根治方案);
4. **通知页是否改成主开关 + 从属开关**(会改变现有 5 个平级开关的结构);
5. **运行时卸载是否要求输入名称确认**(更安全但更重;备选:普通确认弹窗 + 影响说明)。
